# Transformomics v2

Does a spot's spatial neighborhood carry information about its state beyond its own expression
- and can a small transformer use it? v2 turns the v1 proof-of-concept into a testable protocol and
connects it to the microglia programme work.

> Formerly named "SpatialFormer". Renamed to avoid confusion with the unrelated, large-scale pre-trained
> *SpatialFormer* foundation model (Wang, Huang & Winther, bioRxiv 2025, doi:10.1101/2025.01.18.633701).
> The old Hugging Face Space and `legacy/` files still use the old name in their URLs.

> Status: pipeline verified on **synthetic data only** (see `tests/` and `results_synthetic/`).
> No claim about real tissue or microglia has been made with it yet. The gene lists in
> `configs/microglia_programs.yaml` are **placeholders**; replace them with your modules.

## What the synthetic check showed (pipeline sanity only)

- Planted-context data (`--synthetic`, 4 folds, 1 seed): real neighbors beat shuffled/none by ~0.06 mean
  Pearson r in 4/4 folds, and the transformer beat the own+neighbor-mean ridge by ~0.014 (small).
- **Null control** (no spatial signal planted): real still beat shuffled by +0.024 in 3/4 folds, so with 4 folds a gap
  of ~0.02 is within chance. Treat gaps that small as inconclusive; use more folds/sections.
- The `label` task path runs end-to-end (crash test only; synthetic labels are not meaningful).

## What changed vs v1 (`legacy/`)

| v1 issue | v2 |
|---|---|
| Labels = Cell Ranger clusters computed from the same expression (circular) | Primary task predicts **microglial programme scores**; programme genes are **removed from the model input** so the target can't be read off its own genes. v1 task is still available (`label_v1_replication.yaml`). |
| One random 80/20 split, val set used for model selection and reporting | **Spatial-block CV** with separate val (early stopping) and test folds, plus a **buffer** so no training query shares tokens with held-out spots. Several seeds. |
| Never showed neighbors help | **Controls**: `transformer_shuffled` (random neighbors), `transformer_none` (neighbors masked), `ridge/logreg own` and **`own + neighbor-mean`** baselines. |
| Absolute coordinates, one token type for all neighbors | **Relative offsets** (dx, dy, dist in units of median NN spacing), optional learned **distance bias** in attention, random rotation augmentation. |
| README numbers disagreed with notebook | Tables are generated by code (`results/summary.md`). |
| `app.py` zero-padded missing genes at the end (misaligned columns) | Fixed in `legacy/app.py` (aligned to training gene order). |

## Connection to the microglia work

1. **Programmes as modules.** Put your four programmes (homeostatic, phagocytic, NRF2/Hmox1, Apoc1/chemokine)
   in `configs/microglia_programs.yaml`. They are scored per spot/cell (control-subtracted module score).
2. **Spatial structure first.** `programme_spatial_stats.csv` reports Moran's I with a permutation p-value per
   programme. If a programme shows no spatial autocorrelation, that is a result in itself.
3. **Context-dependence.** The transformer predicts programme scores from the spot's own (non-programme)
   expression + neighborhood. If `transformer_real` does not beat `transformer_shuffled` and
   `ridge_own_nbr_mean`, the neighborhood adds nothing beyond smoothing.
4. **Microglia-only queries** (`restrict:` in the config) keep microglia-rich spots as the units being evaluated.

Caveats you should keep in the paper: Visium spots are multi-cell (programme scores are mixtures, not
microglia-intrinsic); programme definitions come from dissociated-cell pseudobulk, so check detected-gene
coverage in the spatial panel (`programme_gene_coverage.csv`); target-from-neighborhood prediction does not
show *causal* niche effects.

## Usage

```bash
pip install -r requirements.txt
pytest -q                                              # unit tests
python -m transformomics.run --synthetic --quick --out results_synthetic/   # smoke test
python -m transformomics.run --config configs/microglia.yaml --out results/
```

Input: `.h5ad` with raw counts in `.X` and coordinates in `.obsm['spatial']`.
Outputs in `--out`: `results.csv`, `summary.csv`, `paired_comparisons.csv`, `programme_spatial_stats.csv`,
`programme_gene_coverage.csv`, `summary.md`, `config_used.json`.

## Real-data experiments (v2.1: multi-section, boundary, saliency, faithfulness)

New in v2.1 (all additive; the single-section pipeline above is unchanged):

| Module | What it does |
|---|---|
| `multisection.py` | Per-section graphs (no cross-section neighbours), training-only HVG/z-score, leave-one-donor/section-out splits |
| `run_multi.py` | Driver: transformer arms + linear baselines per held-out group, **per-spot** losses/attention |
| `boundary.py` | Boundary vs interior tests on attention *and* on neighbour benefit, adjusted for ambiguity/edge/label/section, with per-group consistency |
| `marker_enrichment.py` | Rank-AUC of attribution scores for marker sets vs expression-matched random sets; logreg/DE baselines |
| `interpret.py` | Attention rollout, class-contrastive integrated gradients (query **and** neighbour tokens), deletion test |
| `faithfulness.py` | Does attention put weight on same-domain neighbours more than uniform / inverse-distance / expression-cosine weights? |
| `synthetic_sections.py` | Synthetic multi-section data with planted domains, mixed boundaries, marker genes (plumbing control) |

```bash
python -m transformomics.run_multi --synthetic --quick --out results_synth_multi     # plumbing test
python -m transformomics.run_multi --config configs/dlpfc.yaml --out results_dlpfc    # real data (see docs/DATASETS.md)
python -m transformomics.run_multi --config configs/dlpfc.yaml --null-coords 1 --out results_dlpfc_null   # artefact floor
```
Read `docs/PREREGISTRATION.md` first and fill in thresholds before running on real data. The claims on
boundaries, marker agreement and interpretability are **hypotheses with tests**, not results; none has been
run on real tissue yet.

Status of the tests: the numpy/pandas parts (loading, splits, boundary stats incl. a null-calibration test,
marker enrichment, faithfulness, assembly) are unit-tested. The torch-dependent parts (`nbr_mask`,
integrated-gradients completeness, per-spot attention, `fit_predict` extras, an end-to-end tiny run) have
tests in `tests/test_multi.py` that run when torch is installed (`pytest -q`).

## Suggested next steps

1. Replace placeholder genes with your modules; run on the v1 Visium section as a first look.
2. Add a dataset with real ground truth and several sections (e.g. DLPFC for domain labels) and use
   leave-one-section-out instead of block CV within one section.
3. Prefer single-cell-resolution spatial data (MERFISH/Xenium) if its gene panel covers the programme genes.
4. Only then explore model changes (multi-scale neighborhoods, gene-program tokens).
